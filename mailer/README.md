# ✉️ SilverMail

**複数のメールアカウントと、カレンダー・ToDoをひとつにまとめる、Mac向けローカルクライアント**

iPhoneの「メール」アプリのように複数アカウント（Gmail・iCloud・Yahoo!メール・独自ドメイン等）を統合受信でまとめ、Gmailのようにメールの横へカレンダーとToDoを並べて表示します。メールに書かれた日時はそのままワンクリックで予定にできます。データはすべて自分のMacの中だけで完結します。

## 特徴

- **統合受信ボックス** — 全アカウントの受信メールを1つの一覧に。アカウントカラーの色分けでひと目で見分けられます
- **本物のIMAP/SMTP** — Gmail・iCloud・Yahoo!メール・レンタルサーバー（Xserver・さくら等）に実際に接続。閲覧・検索・送信・返信・転送・添付・フラグ・アーカイブ・フォルダ移動・下書き保存に対応
- **カレンダーとToDoを横に並べて表示** — メールを読みながら右のパネルで今日以降の予定と未完了のToDoを確認できます（Gmailのサイドパネル方式）。月／週／予定リストの全画面カレンダーも内蔵
- **メールから直接スケジュールへ** — 本文の「令和8年9月10日（木）14:00〜16:00」「明日15時から1時間半」といった日本語の日時を自動で読み取り、ワンクリックで予定に登録。件名がタイトル、差出人が参加者、本文がメモに入り、予定からは元のメールへ戻れます。「ToDoに追加」も1クリック
- **Googleカレンダー / Google ToDo と双方向** — 閲覧だけでなく、SilverMailから予定の追加・変更・削除、ToDoの作成・完了までできます。iCalのURL購読（読み取り専用）にも対応し、連携なしで使える「このMacの予定」も用意
- **ToDoの保存先を選べる** — 追加したToDoを**Google ToDo（Google Tasks）のリストに直接入れられます**。リストごとの絞り込みや、「このMac ⇄ Google」の付け替えにも対応。iPhoneやGmailのタスク欄からも同じToDoが見えます
- **プライバシー第一**
  - パスワードと連携トークンは**macOSキーチェーン**に保存（他OSでは `~/.silvermail/` に0600権限で保存）
  - メール内の**リモート画像を既定でブロック**（開封トラッキング対策・ワンクリックで表示可）
  - HTMLメールはサンドボックス化したフレーム＋CSPで隔離表示（スクリプトは実行されません）
  - サーバーは `127.0.0.1` のみで待ち受け。外部Webサイトからのアクセスは拒否（Origin/Hostチェック）
- **日本語メールに強い** — ISO-2022-JP（JIS）・Shift_JIS・EUC-JP・UTF-8を自動判別。一覧のプレビューは1コマンドでまとめて取得するため、50件でも待たされません
- **押し間違えても戻せる** — ゴミ箱・アーカイブ・移動のあと、しばらく **「元に戻す」** が出ます。
  送信も押してから**5秒間は取り消せ**、取り消すと書きかけがそのままの状態で戻ります
- **ToDoはGoogle ToDoと同じ使い勝手** — 押すと詳細が開き、**詳細（メモ）欄**・期限・リストをその場で直せます。
  **サブタスク**にも対応（入れ子は1段まで。親を完了にすると下も完了になります）。
  **「自分の順序」ではドラッグで並べ替え**でき、「日付順」にも切り替えられます。
  **リストの作成・改名・削除**、**完了済みのまとめて削除**もSilverMailから行えます。
  メールから作ったToDoには差出人が出て、**ToDo側から元のメールをそのまま開けます**
  （Googleの仕様上、**スターと繰り返しはAPIに項目が無く再現できません**）
- **Apple Mail風の3ペインUI** — ライト/ダーク対応・ペイン幅の調整・右クリックメニュー・ホバーのクイックアクション（押しやすい大きさ）
- **キーボードで速い** — `↑↓`移動・`E`アーカイブ・`⌫`削除・`F`フラグ・`U`未読・`R`返信・`S`予定を作成・`T`ToDoに追加・`⌘N`新規・`⌘Enter`送信・`/`検索
- **新着チェックとデスクトップ通知** — 設定した間隔で自動受信し、新着を通知（オプトイン）
- **デモモード** — アカウントを繋がなくても、サンプルのメール・予定・ToDoで全機能を試せます

## 必要なもの

- macOS（Apple Silicon / Intel どちらも可）※Linux/Windowsでも動作します
- [Node.js](https://nodejs.org/ja) 18以上（LTS版推奨・`brew install node` でも可）

## はじめかた

```bash
cd mailer
npm install --omit=dev   # 初回のみ（実行用の4パッケージだけが入ります）
npm start                # → ブラウザが自動で開きます（http://localhost:8744）
```

Finderから使う場合は **`SilverMail.command` をダブルクリック**でも起動できます
（初回は 右クリック → 開く。セットアップも自動で行われます）。

まずは試したいだけなら:

```bash
npm run demo             # デモアカウント2つ＋サンプルのメール・予定・ToDo入りで起動
```

終了するには、起動したターミナルで `Ctrl+C` を押します。
別のターミナルからでも `npm run stop` で終了できます。

## アカウントの追加

起動後「アカウントを追加」からプロバイダを選ぶと、サーバー設定は自動で入ります。

| プロバイダ | 準備すること |
|---|---|
| **Gmail**（Google Workspaceの独自ドメインを含む） | Googleアカウントで2段階認証を有効にし、[アプリパスワード](https://myaccount.google.com/apppasswords)（16文字）を作成して、そのパスワードで追加。通常のログインパスワードでは接続できません |
| **iCloud** | [appleid.apple.com](https://account.apple.com/) →「サインインとセキュリティ」→「アプリ用パスワード」を発行 |
| **Yahoo!メール** | Yahoo!メールの設定で「IMAP・POP・SMTPアクセス」を有効化 |
| **独自ドメイン**（Xserver・さくら等） | 「その他」を選び、メールアドレス入力後「サーバーを自動検出」。検出できない場合は契約時のメール設定情報（IMAP/SMTPホスト名）を入力 |

追加前に「接続テスト」で受信（IMAP）・送信（SMTP）の両方を確認できます。

> **Outlook.com（個人）について**: Microsoftは個人アカウントのIMAP基本認証を廃止したため接続できない場合があります。Microsoft 365（組織）は管理者がIMAP/SMTP AUTHを許可していれば利用できます。

## カレンダーとToDoの接続

右パネルの歯車、またはカレンダー画面下の「カレンダーを追加・管理」から設定します。方式は3つあります。

| 方式 | できること | 準備 |
|---|---|---|
| **このMacの予定** | 追加・変更・削除（このMacの中だけ） | 不要（最初から使えます） |
| **URLで購読（iCal / .ics）** | 表示のみ | Googleカレンダーの「設定と共有」→「カレンダーの統合」→**限定公開URL（iCal形式）**を貼り付け |
| **Googleカレンダー / Google ToDo** | 表示・追加・変更・削除、ToDoの作成と完了 | 下記のとおりGoogle側でクライアントIDを1回作ります |

### Googleカレンダーを接続する手順

Googleは、メールのアプリパスワードではカレンダーAPIを許可していません。ご自身のGoogleアカウントで一度だけ「このMacのSilverMailからアクセスしてよい」という鍵（OAuthクライアントID）を作ります。

1. [Google Cloud Console](https://console.cloud.google.com/apis/credentials) を開き、プロジェクトを作る（既存のものでも可）
2. 「APIとサービス」→「ライブラリ」から **Google Calendar API** と **Google Tasks API** を有効にする
3. 「OAuth同意画面」で User Type を選ぶ。**Google Workspaceなら「内部」**が手間なし（審査もテストユーザー登録も不要）
4. 「認証情報を作成」→「OAuth クライアント ID」→ アプリケーションの種類は **ウェブ アプリケーション**
5. 「承認済みのリダイレクト URI」に次を**そのまま**登録する（末尾のスラッシュなし）

   ```
   http://127.0.0.1:8744/api/oauth/google/callback
   ```

6. 表示された **クライアントID** と **クライアントシークレット** を、SilverMailの接続画面に貼り付ける
7. **「設定を確認」** を押す → 「正しく認識されました」と出たら **「Googleにログインして許可する」**

> 入力したクライアントIDは次回以降も画面に残ります。シークレットも控えられるので、
> 接続をやり直すときは**空欄のままで構いません**（変更するときだけ入力してください）。

> **「設定を確認」について**: ブラウザを開く前に、**実際の接続と同じ方式**（認可コードの引き換え）で
> クライアントID・シークレット・リダイレクトURIの登録をまとめて確かめます。わざと通らない認可コードを
> 送り、返るエラーの種類で判定するだけなので、トークンは発行されません。
> 通らない設定のまま許可画面へ進んでも徒労なので、その場合は理由を表示して開かないようにしています。
>
> 個人のGoogleアカウント（Workspaceでない）で作る場合は、User Typeが「外部」になります。
> その際は**テストユーザーにご自身のアドレスを追加**してください。ただしテスト状態のままだと
> **更新用トークンが7日で失効**するため、「本番環境に公開」まで進めることをおすすめします。

クライアントシークレットと更新用トークンはmacOSキーチェーンに保存され、リポジトリやファイルに平文で残りません。連携を解除すると、SilverMailからトークンを失効させます（Google側の予定は消えません）。

### ToDoをGoogle ToDoに入れる

Googleカレンダーを接続すると、**Google ToDo（Google Tasks）のリストがそのまま保存先の候補**になります。

- ToDoタブの追加欄の右にある**保存先ボタン**を押すと、`このMacのToDo` とGoogle側のリストが並びます。選んだ先が以後の既定になります（メールからの「ToDoに追加」も同じ先へ入ります）
- 追加欄の上の**リストチップ**で、表示するリストを絞り込めます
- 既存のToDoは「⋯」メニューの **`◯◯ へ移動`** で、このMac ⇄ Google の間を行き来できます
- Google側に入れたToDoは、iPhoneのGoogleカレンダーアプリやGmailのタスク欄からも見えます。完了のチェックは双方向に反映されます

> Google ToDoの期限は**日付だけ**を持つ仕様のため、時刻は保存されません（SilverMail側でも日付として扱います）。

### メールから予定・ToDoを作る

メールを開くと、本文に日時があれば「このメールに日時が書かれています」と候補が並びます。

- **カレンダーに追加** — 件名がタイトル、日時が開始・終了、差出人が参加者、本文がメモに入った状態で作成画面が開きます
- **ツールバーの 📅 / ✓**（または `S` / `T`）— 予定の作成／ToDoへの追加。ToDoには期限として最初の候補日が入り、選んでおいた保存先（このMac または Google ToDo）へ入ります
- 予定・ToDoからは **元のメールに戻れます**

読み取れる書き方の例:
`令和8年9月10日（木）14:00〜16:00` / `2026/9/1` / `8月20日 10:00から30分` /
`明日 15時から1時間半` / `来週の火曜 午後2時30分` / `今度の日曜日` / `９月１０日　１４：００`

## データの保存場所

| 内容 | 場所 |
|---|---|
| アカウント設定 | `~/.silvermail/accounts.json`（0600） |
| パスワード・連携トークン | macOSキーチェーン（サービス名 `SilverMail`）／他OSは設定ファイル内 |
| カレンダーの接続先 | `~/.silvermail/calendars.json` |
| このMacの予定・ToDo | `~/.silvermail/local-events.json` / `tasks.json` |
| ToDoの既定の保存先 | `~/.silvermail/settings.json`（`defaultTaskList`） |
| Google連携の入力途中の控え | `~/.silvermail/google-draft.json`（0600・シークレットはキーチェーン） |
| アプリ設定 | `~/.silvermail/settings.json` |

メール本文はサーバー（IMAP）側に置いたまま都度取得します。ローカルへの全文複製は行いません。
Googleカレンダーの予定も都度取得で、ローカルには保存しません。
アカウントを削除してもサーバー上のメールは消えません。

## 既知の制限

- スレッド（会話）表示は未対応（一覧は新着順）
- **メール**のOAuth認証（Outlook.com個人など）は未対応。アプリパスワード方式のプロバイダをご利用ください
- 送信はテキストメール（+自動生成のHTMLパート）。リッチテキスト編集は未対応
- カレンダーの繰り返し予定は、SilverMailからは**単発の予定としてのみ**作成できます（既存の繰り返し予定の表示には対応）
- 購読URL（iCal）のカレンダーは読み取り専用です

## トラブルシューティング

### まず接続診断（Google連携がうまくいかないとき）

原因を一か所ずつ手で確かめる必要はありません。設定の控え・Googleへの問い合わせ・
連携済みカレンダーの疎通を**実際にGoogleへ送って**順に確かめ、どこで止まっているかと、
次にやることを出します。

**画面から** — 「カレンダーとToDoの接続」を開き、右下の **「接続を診断」** を押します。

**ターミナルから**

```bash
npm --prefix mailer run diag
```

どちらも同じ判定（`server/diagnose.js`）を使うので、結論が食い違うことはありません。

```
  ● 設定の控え
    ✓ クライアントID  72文字
    ✓ シークレット  35文字（末尾 ****）

  ● Googleへの問い合わせ
    ✓ クライアントID・シークレット・リダイレクトURI  すべて一致

  ● 連携済みのGoogleカレンダー（1件）
    ✓ 認証  アクセストークンを取得できました
    ✗ Google Calendar API  有効になっていません
       → Google Calendar API を有効にしてください
         https://console.cloud.google.com/apis/library/calendar-json.googleapis.com?project=...
```

出力はそのまま貼って共有できます。**シークレットは長さと末尾4文字しか出ません。**
ターミナル版は、問題がなければ終了コード0、あれば1で終わります。

### `npm run check:google`（案内が的外れになっていないか）

このアプリは、Googleが返す `invalid_client` を説明文から「IDが違う」「シークレットが違う」に
読み分けています。根拠は文言だけで、仕様として約束されたものではありません。
Googleが文言を変えると、静かに誤った案内を出し続けることになります。

```bash
npm --prefix mailer run check:google
```

実際のGoogleへ、わざと通らない値を送って読み分けが今も成り立つかを確かめます
（トークンは発行されません）。想定と違えば、直す場所まで出します。

### 個別の症状

- **「ログインを拒否されました」** — Gmail/iCloudは通常のパスワードではなく**アプリパスワード**が必要です。
  独自ドメインのアドレス（例: `you@your-company.com`）でGmailプリセットを使えるのは、そのドメインが
  **Google Workspaceで運用されている場合のみ**です。レンタルサーバーのメールであれば「その他」を選び、
  契約先のIMAP/SMTPホスト名を入力してください
- **「ポート 8744 はすでに使用中です」** — 古いSilverMailが残っています。`npm run stop` で終了してから `npm start` してください。
  この状態でブラウザに表示されているのは**更新前の古い画面**なので、更新後は必ず起動し直してください
  （`PORT=8745 npm start` で別ポートに変えることもできます）
- **直したはずの不具合が直っていない** — たいていは更新が反映されていないだけです。
  接続画面の右下と、起動したターミナルに **「アプリの版」** が出ます。ここが最新でなければ、
  `git pull origin main` のあと `npm run stop` → `npm start` で起動し直し、
  ブラウザは **⌘ + Shift + R**（強制リロード）してください。
  版はコマンドでも確認できます: `curl -s http://localhost:8744/api/health`
- **`invalid_client` と出る** — Googleはこのエラーを**ふたつの意味**で返します。説明文で見分けられます。
  失敗した画面が、どちらなのかを名指しします（この画面は自動で閉じません）。

  | Googleの説明文 | 意味 | 直すところ |
  | --- | --- | --- |
  | `The OAuth client was not found.` | クライアントIDが見つからない | **クライアントID** |
  | `The provided client secret is invalid.` / `Unauthorized` | IDは実在し、シークレットだけ違う | **シークレット** |

  前者はIDに**余分な空白・全角空白・見えない文字**が混ざっているか、**末尾が欠けている**ときに起こります
  （末尾は `.apps.googleusercontent.com` で終わっているはずです）。削除したクライアントを使った場合も同じです。
  後者は「シークレットを追加」で新しく発行し、コピーアイコンで取得して貼り直してください
  （**「表示」で実際に入っている値を確認**できます。ブラウザのパスワード管理が古い値を入れていることがあります）。

  どちらか分からないときは、接続画面の **「設定を確認」** を押せばその場で切り分けられます。
  端末からも確かめられます（クライアントIDは秘密ではないので、シークレットはでたらめで構いません）:

  ```bash
  curl -s -X POST https://oauth2.googleapis.com/token \
    -d client_id='ここにクライアントID' -d client_secret='dummy' \
    -d grant_type=refresh_token -d refresh_token=dummy
  ```

  `client secret is invalid` が返れば、そのクライアントIDは**正しい**という意味です。

  なお `4aad000` 以前の版には、保存した認証情報を読み出すときにクライアントIDが抜け落ち、
  `client_id=undefined` として送ってしまう不具合がありました。設定が正しくてもこのエラーになります。
  失敗した画面の「失敗した段階」が**カレンダー一覧の取り込み**と出ていたら、それはこの不具合です。
  `git pull origin main` で更新してください。
- **「あと一歩です」と出て、APIを有効にするよう促される** — 認証は通っており、
  Google Cloud Console でそのAPIを一度有効にするだけで済みます。画面のリンクから直接開けます。
  カレンダーは **Google Calendar API**、ToDoは **Google Tasks API** の両方が必要です。
  有効にした直後は、反映まで数分かかることがあります。
- **Googleの許可画面で「アクセスをブロック」と出る** — 同意画面が「外部」かつテストユーザー未登録の可能性があります。
  ご自身のGoogleアドレスをテストユーザーに追加してください。
  なお同意画面を**「内部」にすると、組織外のアカウント（個人のGmailなど）は接続できません**。
  個人アカウントも繋ぎたい場合は、そのアカウント側で別のクライアントIDを作るか、
  カレンダーを組織アカウントへ共有してください（共有なら追加設定なしで読み書きできます）
- **組織アカウントで弾かれる** — 管理コンソール → セキュリティ → APIの制御 で、
  作成したクライアントIDが許可されているかご確認ください
- **「更新用トークンを受け取れませんでした」** — 以前に同じクライアントIDで許可済みの状態です。
  [Googleアカウントのサードパーティアクセス](https://myaccount.google.com/connections)から一度解除して、もう一度お試しください
- **`PORT=8745` で起動している場合のGoogle連携** — リダイレクトURIもそのポートになります。接続画面に表示されたURIをそのまま登録してください
- **会社のメールに繋がらない** — IMAPが無効化されている場合があります。メールサーバーの管理者にIMAP/SMTPのホスト名とポートをご確認ください
- **画面は出るのに操作すると「サーバーに接続できません」** — `npm start` を実行したターミナルが閉じていないか確認してください。
  ターミナルにエラーが出て停止している場合は、その内容を添えてIssueでお知らせください
