# 給与 の決まり（CLAUDE.md §3 から移した・文は一字一句そのまま）

このファイルは、上の paths のファイルを Read・Edit・Write した時に読まれる。grep・sed だけで触る時は、触る前にこのファイルを読む。全画面に効く決まり（§1・§2・§4〜§10 と §3 の横断の項目）は CLAUDE.md にある。

- 給与（`payroll.html`）の決まり（凍結した仕様と給与 v1 の契約 2026-11-19 の要点・本人指示 2026-11-21 でここへ移した）:
  - 正本は共通 DB（統合 0102・0103・0105・0110・0118・0119）。表には読む・書く権限を誰にも渡さず（表を直接は誰も読めない）、関数だけが読み書きする。計算は画面の純関数（`payroll-calc.js`）で行い、データベースは保存・権限・入力の指紋の照合・合計の数え直し・監査の記録を受け持つ。
  - 使えるのは管理者と給与の名簿に載せた事務所のアカウントだけで、どちらも2段階のログイン（aal2）が要る。現場の役割は名簿にあっても通さない。誰が使えるかはデータベースの関数が決め、画面は `SUAppGate.run('payroll')` の後に関数の答えで覆いの画面を出す（aal2 が無い時は2段階認証へ案内する）。給与の名簿・給与の設定・手当の定義の変更と確定の取り消しは管理者だけ。
  - 給与を開くには、名簿と aal2 に加えて、そのログインで本人の給与専用の暗証番号（4〜6桁）を入れて鍵を開ける。開いているのは10分で、さわると延びる。続けて違えると止める（止めるたびに長く）。管理者だけの関数も鍵が開いている時だけ通す（0110・0119）。忘れた人の番号を消すのは管理者だけで、自分の番号は消せない。暗証番号の表は給与の控えと全データの書き出しに入れない。
  - 振込先の口座は別の表に暗号化して置き、画面に出すのは下4桁と銀行名だけ。画面が口座の全桁を受け取るのは全銀の振込データを書き出す時だけ（`payroll_bank_export`・受け取りを監査に残し、ファイルを作ったらすぐ捨てる）。全銀の書き出しは給与の設定で使うと決めた時だけ出す。
  - 給与の表は毎晩のバックアップから外し、給与だけを別の読み口で取って暗号化して控える（0105）。
  - 率と税額表は一次資料で確かめた値だけを書き、出典を表に書く。確かめられない値・表の無い年は null にし、別の値で代えずに警告を出す（記憶で埋めない）。税額表は支給日の年で引く。
  - 下書きの保存は勤怠のその月分を締めてから。確定は押した時に読み直して数え直し、データベースが入力の指紋と合計を照らし合わせ、違えば断る。確定した月は保存し直せず、確定の取り消しは理由つき。勤怠は締めの控えと数え直しを比べ、食い違えば止める。金額の変更・確定・取り消し・書き出しは監査に残す。率・雇用保険の率・税額表・標準報酬が無い警告のある明細は、データベースも確定させない。前に書き出した月の振込データをもう一度出す時は、同じ人の10分以内の確かめの記録が要る（0118）。
  - 金額は円の整数。端数・丸めは `payroll-calc.js` の中だけで決め、境目を試験で押さえる。試験・見本は架空の職員と架空の金額だけで、実在の職員の給与・口座はどこにも書かない。
  - 勤怠管理から `?ym=YYYY-MM&from=kintai` で来た印は、from が kintai と完全に同じで ym が形どおりの時だけ使い（ホワイトリスト）、起動の時に1回だけ読んで URL から外し、メモリだけに持つ（端末に残さない・鍵の画面を越えて残す）。締めた勤怠の確かめが決まった後に1回だけ判定して印を消し、月分・タブを変えたら捨てる。自動で「計算する」と同じ関数を呼ぶのは、勤怠が締めてあり確かめが合い・確定していない・計算も未保存の編集も無い・下書きが無いか stale の時だけで、未締め・確定済み・下書きありは帯で知らせるだけ、勤怠の食い違いでは何もしない。自動で計算した時は受け取りの帯だけを出し（「まだ保存していません」の帯とトーストは出さない）、人が何も変えていない間は離れる時の確かめ（読み込み直し・月分を変える・ほかの画面へ）に数えない。人が計算し直す・調整を変えると、帯を消して普通の未保存の扱いに戻す。下書き保存と確定は自動でしない（2026-11-26・文は仮置き）。締めてあって保存した物（下書き・確定）が無い月分は、印が無くても今月の給与のタブを開いた時（月分を変えた・読み直した・鍵や覆いの後・タブを切り替えた時も）に、同じ読み込みで1回だけ自動で計算する（読むだけ・保存と確定は人が押す・stale の計算し直しと走らせなかった理由の帯は印がある時だけ・読み直しでは自動で計算しただけの結果を持ち越さない・計算できる人が0人なら結果を残さない・2026-11-26・文は仮置き）。
- 賞与（`payroll.js` の賞与のタブ・計算は `payroll-calc.js` の computeBonus・保存先は共通 DB の統合 0121）の決まり:
  - 読み書きは 0121 の関数9本（payroll_bonus_bootstrap・_create・_config_put・_save・_confirm・_unconfirm・_delete・_bank_export・_export_log）だけ。関数の無い DB では「賞与はまだ使えません（データベースの準備中）」と出して何もしない。
  - 保存する明細は computeBonus の出力をそのまま送らず、0121 が許す鍵だけに写す。
  - 前月の給与は、自社の確定した明細 ＞ 年末調整の記録 ＞ 手入力（金額か「前月の給与なし」）の順で決める。記録から取った値も手入力として送る。年末調整の記録の答えが決まるまで下書き保存と確定を押させない。黙って「前月の給与なし」に落とさない。
  - 確定できない警告（computeBonus の止めと、前月の給与が無い・未確定）が残る回は確定させない（データベースも断る）。
  - 端末に残すのは開いていたタブだけ。金額・氏名は残さず、10分で描いた金額を捨てる。
  - 振込データは全銀の種別12・振込指定日は支給日。賞与支払届に写す値の CSV に個人番号・基礎年金番号は出さない。
  - 前月の給与が無い・賞与が前月の給与の10倍を超える時の月額表の方法は、税額表（月額表）だけで数え、電算機特例は使わない。
  - 回の対象（支給日に給与の設定がある在籍の職員・支給日より前に退職した人は除く）は誰も外さない。賞与額が空の人がいる回は画面が確定させない（払わない人は 0 を入れ、総支給0の明細にする・代表者の答え 2026-11-23）。この止めは画面だけで、データベースは明細が1件以上あれば確定を受ける。総支給0の人は明細の印刷・振込データ・賞与支払届の CSV に出さない。
  - 手当の行（賞与額のほかの支給・控除）はまだ扱わない。
