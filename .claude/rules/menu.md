# メニュー の決まり（CLAUDE.md §3 から移した・文は一字一句そのまま）

このファイルは、上の paths のファイルを Read・Edit・Write した時に読まれる。grep・sed だけで触る時は、触る前にこのファイルを読む。全画面に効く決まり（§1・§2・§4〜§10 と §3 の横断の項目）は CLAUDE.md にある。

- メニューの「個別機能訓練計画書」のタイルには、計画書を事務所PCで開いた時に数えた期限の件数（超過・要注意・計画なし）と数えた日を札で出す。端末に残すのは件数と日付だけ（氏名・利用者Noは残さない）で、メニューは読むだけ（通信しない・現場端末では読まない）。件数が全部0件の時・読めない時は今と同じ見た目にする（代表者の決定 2026-10-24 案A）。

- メニューの「設備・修繕の記録」のタイルには、設備の記録を事務所PCで開いた時に予定の一覧（equip-calc.js の schedule）から数えた期限切れ・30日以内の数と数えた日を札で出し、「法定」の印の設備の期限切れは別の赤の札（地 --due-tx・文字は白）にする。端末に残すのは件数と日付だけ（eql_menu_due・設備名と場所は残さない・読めない時は書かない）で、メニューは読むだけ（通信しない・現場端末では読まない）。「法定」の印は新しい列を作らず、設備に付ける選択肢の項目（増やした項目）で「法定」を選んだ設備とする（使わない項目の値は数えない）。全部0件の時・読めない時は今と同じ見た目（代表者の指示 2026-11-13）。
- メニューの「担当者会議の記録」のタイルには、担当者会議のページの「入居者を選ぶ」画面が事務所PCで共有名簿と最終開催日の要約を読めた時に、前回から6か月の期限切れ（今日で6か月を含む）と30日以内の数（在籍・入院していない方・care-meeting-calc.js の menuDueSummary が dueAlerts で数える）と数えた日を札で出し、注記「6か月の分だけ」を付ける（認定の更新・区分変更・退院の後は数えない）。端末に残すのは件数と日付だけ（cm_menu_due・氏名・番号は残さない・読めない時と現場端末では書かない）で、メニューは読むだけ（通信しない・現場端末では読まない）。全部0件の時・読めない時は今と同じ見た目（代表者の決定 2026-11-13・仮置き）。

- メニュー（index.html）のボタンは、ログインの役割（管理者・事務所・現場）ごとに、管理者が「メニューの設定」（menu-settings.html・管理者＋2段階認証だけ）で決めた並び・非表示で出す。並べ替え・非表示の当て方は `su-menu.js`（試験は `check/unit/menu_arrange_test.js`）、保存先は共通 DB の menu_settings。ログインしていない端末・設定を読めない時は既定の並びで出す。現場端末で事務所専用を出さない仕組みは設定で外せない。「使い方・困った時」は隠せない。これは入口の整理で守りではない（代表者の決定 2026-10-23）。
  役割の決まり（`SUMenu.view`・設定が無くても効き、設定では外せない）: 管理者専用（定義の adminOnly・今は採用管理）は管理者にだけ出す（ログインしていない端末にも出さない）。事務所専用は現場のアカウントでは事務所PCでも出さない。ログインの記録があって役割がまだ分からない間は事務所専用を出さず、確かめられなければログインしていない時の既定に倒す。見出しの下に今の役割の帯（「管理者としてログイン中」等・画面だけ）を出す（本人承認 2026-10-29）。
  メニューの下の欄の「動作の速さの記録」のリンクは、事務所の端末で事務所・管理者としてログインしている時だけ出す（現場端末では管理者でも出さない・現場のアカウント・ログインしていない・役割がまだ分からない時も出さない・初めは隠して役割が分かってから出す・判定は `SUMenu.perfLinkShown`・試験は `check/unit/menu_arrange_test.js`）。記録そのもの（`su-perf.js`）は今までどおり全端末で取る（代表者の決定 2026-11-14・現場端末の管理者に出さないのは仮置き）。
- メニューの見出しの毬は、藤の手毬・菊かがり・麻の葉の3つの柄で、出ている業務ツールの数で育つ（数えるのは設定・困った時の区分を除いたツール。現場端末で隠れる事務所専用は数えない）。既定は藤の手毬で、押すと 藤の手毬 → 菊かがり → 麻の葉 の順に切り替わる。毬を押した柄はその端末だけに残し（`su_menu_ball`・書くのは `su-menu.js` だけ）、施設の既定は「メニューの設定」で藤の手毬か麻の葉を選ぶ（共通 DB は統合 0025・キー無し＝藤の手毬。菊かがりは各端末で毬を押して選ぶ）。毬は図形の属性だけで描き、外からの文字を入れない。アプリのアイコンは菊かがりの完成形のまま（代表者の決定 2026-10-26・藤の手毬は本人指示 2026-11-10）。
- メニューの見た目は「つむぐケア」の色味（生成りの見出しに藍の字）。PC（幅900px以上）は4列で並び順のまま左から詰め（組の行割り newrow は使わない）、絵の右に名前を置き、絵の地を毬のロゴの5色（業務ツールの分野ごと・設定と困った時は無地）にする。それより狭い画面は色味だけ変え、ボタンの形と高さ・2列・絵の下に名前・組の行割りは今のまま。印刷は変えない（全部 @media screen の中・試験 menu_look_test）（代表者の決定 2026-10-29）。
- メニューの区分（職員・入居者など）は、管理者が「メニューの設定」で作る・名前と絵文字を変える・消す（中のボタンを全部ほかの区分へ移した後だけ）・ボタンを別の区分へ移すことができる（保存は共通 DB 0023 の sdef・gone・mv）。施設名を含む区分の名前は定義に `{{通所}}` 等で書く。設定に無い区分（後から足した区分）は既定で前にある区分の直後に出し、事務所専用の区分から移したボタンは移した先でも現場端末に出さない。入居者の直後に「デイ {{通所}}」の区分を置き、デイ利用表・個別機能訓練計画書・デイの今日の記録を入れる（本人指示 2026-10-26）。
- メニュー（index.html）だけが `manifest.webmanifest` を読み、ホーム画面に追加した時は名前「介護ツール」（仮置き・施設名と製品名は入れない）とアプリのアイコン（菊かがりの完成形・`app-icon-192.png`・`app-icon-512.png`・`app-icon-maskable-512.png`・iPhone 用の `apple-touch-icon.png`）で出し、アイコンから開くと standalone（開く所はメニュー・範囲はこのサイトの中）で開く。住所は相対だけで書き、iPhone の全画面を強める指定（apple-mobile-web-app-capable）は入れない。iOS 26 の「Webアプリとして開く」で開くと Safari と保存領域が分かれる（ログイン・端末の用途・接続設定は入れ直し）ので、現場の iPhone は「Webアプリとして開く」を切って追加する手順を既定にする。試験は `check/unit/app_manifest_test.js`（本人指示 2026-11-21「作って」）。
