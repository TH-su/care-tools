# 週間計画 の決まり（CLAUDE.md §3 から移した・文は一字一句そのまま）

このファイルは、上の paths のファイルを Read・Edit・Write した時に読まれる。grep・sed だけで触る時は、触る前にこのファイルを読む。全画面に効く決まり（§1・§2・§4〜§10 と §3 の横断の項目）は CLAUDE.md にある。

（CLAUDE.md §3「部品・画面ごとの決まり（2026-10 の開発の記録から集めたもの・2026-10-26 にここへ移した）」の中にあった項目）
  - 週間計画は、裏に隠れている画面を描き直さず、見えた時に1回だけ描く。
  - 週間計画の介護度は入居者マスタを正にする（居室と同じ）。入居者マスタとつながっている方（masterId のある方）は、マスタの介護度が入っていればいつも週間計画をそれにそろえ、週間計画の中（介護情報の窓・一括編集）では介護度を直せないようにして「介護度は入居者マスタで直してください」と出す（代表者の決定 2026-11-02「マスタを正にする」）。
  - 週間計画の「計画の版」（2026-11-27 代表者の依頼）: 利用者に予約（nextPlans）と今の計画の印（planFrom・planGen・planLevel・planNote・planGone）を持たせ、決まりは care-plan-calc.js の純関数だけにする。盤面と、ほかの画面が読む events はいつも今の計画。ワークスケジュールは、開いた日が切替日以降なら予約の計画で盤面を作る（切替の前でも）。予約の無い利用者の中身と動きは1バイトも変えない。
  - 切替日（日本時間）を過ぎた予約を今の計画へ入れ替えるのは共通 DB の関数（cs_plan_switch・定時の仕事と画面の呼び出し）が正。口が無い・断られた時だけ画面に帯と［今すぐ切り替える］（人が押す・今ある保存の道）を出し、黙って端末で切り替えない。
  - 切替で使った予約（入れ替えた予約・同じ開始日で負けた予約）は planGone に {id, at: その予約の開始日} で載せる（時計を使わない）。
  - 統合は世代（planGen）の大きい方、世代が同じで開始日（planFrom・文字でなければ空と読む）が違う時はいつもサーバーの方の利用者の予定・今の計画の印を丸ごと採り、別の計画どうしの予定を id で混ぜない。予約はどの場合も両方の id の和から両方の planGone を引いたもの。捨てたこの端末の未送信の変更（足した・変えた・消した・入浴）は件数を知らせる。
  - 端末の控えからの復元は、控えの計画が今より前の方には予定を足さず、丸ごとの復元でもその方は今の計画のまま（人数を知らせる）。世代を小さくしない。
  - 介護度は予約の編集（試算の砂場の kind 'plan'）の中だけ選べる（入居者マスタとつながっている方も・その計画だけの介護度）。切替日からは入居者マスタが正。次の予約の介護度にマスタが先に変わっていても、その予約が切り替わるまで（切替日を過ぎても切り替わっていない間も）今の介護度で計算する（hold）。予約の介護度・メモが文字でない時は空とみなす。予約として作った介護度とマスタが違う時は知らせる（mismatch）。決まりは care-plan-calc.js の resolveLevel の1つ。
  - 予約の編集・過去の計画を見る間は、本物のキー（care_schedule_v2）へ書かない・送らない（試算の守りをそのまま使う）。予約は「予約を保存」を押した時だけ nextPlans に入る。A3 週間予定表はこの間も刷れ、紙は変えない。
  - 版の印: 週間計画を新しい保存先へ送る写しにだけ、最上位に csAppVer（今は 2026112701）を足す（週間計画・デイ利用表の画面のコードが足す・保存先を切り替える共通部品には足さない）。足すのは共通 DB の口 cs_plan_gate が ok:true を答えた（移行 0136 がある）と分かっている時だけで、答えはそのタブのメモリにだけ覚える（あり は覚えたまま・なし とエラーは5分後に確かめ直す）。まだ確かめていない・確かめられない時は印を付けずに送り、送信を待たせない（予約か世代1以上の方がいる中身の時だけ答えを最大3秒待つ）。DB・端末の控え・Google へ送る本文・統合の結果には入れず、受け取ったデータ・別タブの書いた控えに紛れていたら捨てる。共通 DB は予約か世代1以上の利用者がいるデータで印の無い保存を断り（oldapp）、画面は送り直さずに「この画面は古い版です。読み込み直してください」を出す。計画の版の部品（care-plan-calc.js）が読めない端末は、版の項目を持つデータを統合・送信しない（版の項目を誰も持たないデータでは今までどおり）。
  - 予約の機能（作る・直す・開始日を変える・取り消す・今すぐ切り替える）は、新しい保存先の本番の道・事務所の端末・事務所か管理者としてログインしていて、共通 DB の使い始めのスイッチ（cs_plan_status の enabled）が入の時だけ出す。それ以外は今ある予約と今の計画を見るだけ。スイッチが切の間は切替の見張りもしない。
  - 共通 DB が中身を確かめて断った保存（planstale: 世代が下がる・同じ世代で開始日が違う・使った予約が戻る）は、競合と同じ道（取得 → 統合 → 1回だけ送り直す）に乗せ、送り直しも断られたら止めて知らせる。強制保存は、サーバーより計画の世代が小さい方がいる時・planstale の時は行わない（切り替えた後の計画を前の計画で上書きしない）。別タブが前の計画の中身を書いた時は、丸ごと読み込まず統合で取り込む。
